Rails 8.1.4.1 fixes critical Active Storage `CVE-2026-122006`. The same rebuild
updates Ruby to 4.0.10, RubyGems and Bundler to 4.0.24, build-time Node to
24.22.3, the Rails browser packages, and the affected Ruby gems. Addressable
was also updated: it is not installed in the production image but was flagged
in the Ruby lockfile. Mailpit and RustFS use local Dockerfiles to apply the
Alpine OpenSSL updates missing from their upstream images.

**One critical finding remains:** `CVE-2026-6653` in Debian's `libxml2`. Trivy
lists no fixed Trixie package, and the [Debian tracker][debian] marks Trixie
as vulnerable. Rebuild and rescan when a fix becomes available. The app image
is not CVE-free.

[debian]: https://security-tracker.debian.org/tracker/CVE-2026-6653

The rebuilt app passed `zeitwerk:check` and all 101 Playwright Chromium tests
with retries disabled on a fresh, isolated production Compose stack.
StandardRB and the GitHub Actions workflow lint also passed.

The [CI workflow](../.github/workflows/ci.yml) contains the reproducible scan
commands and rejects any finding with an available fix before publishing. Use
`--pull --no-cache` for manual rebuilds when refreshing distro packages. Back up
existing database and object-storage volumes before rolling out the Compose
updates; this audit does not verify in-place upgrades of existing data.
